# 用户管理与额度

## 身份模型

系统同时支持访客、普通用户、管理员三种身份。

| 身份 | 额度来源 | 使用统计 | 管理能力 |
| --- | --- | --- | --- |
| 访客 | `guest_image_quota_limit` 或访客自身额度 | 按 IP 和设备指纹统计 | 无 |
| 普通用户 | `user_image_quota_limit` 或用户自身额度 | 按 `user|用户ID|设备指纹` 统计 | 无 |
| 管理员 | 无限 | 可记录但不限制 | 用户管理、设置、账号池、日志等 |

## 登录与访客迁移

未登录访问 `/image` 时，服务会：

1. 根据客户端 IP 和 `X-Device-Fingerprint` 创建或读取访客。
2. 返回访客身份和额度。
3. 使用图片功能时按访客 key 计数。

普通用户登录成功后，系统会把同设备访客数据迁移到该用户：

- 访客额度使用记录迁移到 `user|用户ID|设备指纹`。
- 访客图片任务的 `owner` 和 `quota_key` 改为用户 key。
- 访客分享奖励归属改为用户。
- 访客档案进入用户的 `converted_guests`。

迁移时必须排除 `user|` 和 `admin|` 前缀，避免管理员使用记录被误迁移。

## 用户列表字段

管理员页面 `/users` 使用 `GET /api/web-users`，返回：

| 字段 | 说明 |
| --- | --- |
| `id` | 用户 ID。 |
| `username` | 登录名或访客名。 |
| `name` | 展示名称。 |
| `role` | `admin`、`user`、`guest`。 |
| `created_at` | 创建时间，可排序。 |
| `last_used_at` | 最后登录或使用时间，可排序。 |
| `active_sessions` | 有效登录设备数。 |
| `device_count` | 设备数量。 |
| `used_total` | 已使用图片数量，可排序。 |
| `quota_limit` | 总额度，`-1` 表示无限。 |
| `remaining_total` | 剩余额度。 |
| `quota_package` | 当前有效套餐，例如 `7d-100`。 |
| `quota_expires_at` | 套餐到期时间。 |
| `device_usages` | 每个设备的使用情况。 |

## 默认额度

默认额度在用户管理页面配置：

- 普通用户默认额度：`user_image_quota_limit`。
- 访客默认额度：`guest_image_quota_limit`。

默认额度只影响没有单独设置额度的身份。已有用户如果已经写入 `quota_limit`，会优先使用用户自身额度。

## 图片额度设置

管理员给用户设置图片额度时，当前实现遵循“追加可用额度”规则：

```text
新总额度 = 当前总额度 + 输入额度
已使用额度不清零
新可用额度 = 新总额度 - 已使用额度
```

如果输入负数，则设置为无限额度：

```text
quota_limit = -1
```

无限额度展示为“无限”，不按剩余额度限制。

## 7 天 100 张套餐

套餐按钮会调用：

```http
POST /api/web-users/{user_id}/quota-package
```

默认请求：

```json
{
  "quota_limit": 100,
  "days": 7
}
```

计算方式只追加到当前额度，不清空已使用数量：

```text
套餐后总额度 = 当前有效总额度 + 100
套餐后可用额度 = 当前可用额度 + 100
```

示例：

```text
当前可用/总额度 = 9998/9999
点击 7 天 100 张
结果 = 10098/10099
```

套餐写入字段：

| 字段 | 值 |
| --- | --- |
| `quota_package` | `7d-100` |
| `quota_package_base_limit` | 套餐前总额度 |
| `quota_expires_at` | 当前时间加 7 天 |
| `quota_limit` | 套餐前总额度加 100 |

到期后有效总额度恢复到 `quota_package_base_limit`。如果套餐内 100 张都未使用，则示例会从 `10098/10099` 恢复为 `9998/9999`。

## 使用额度统计

使用额度来自两部分：

1. `data/ip_image_quotas.json` 的计数。
2. `data/ip_image_tasks.json` 中成功任务的图片数量。

系统取两者中较大的结果或合并结果，目的是避免以下情况漏算：

- 任务成功但计数文件未及时写入。
- 旧任务只有任务记录，没有完整额度记录。
- 用户登录前后的访客记录需要迁移。

管理员无限额度不受限制；普通用户和访客会按 `remaining_total` 限制生成。

## 分享奖励

分享链接由 `/api/ip-limited/share-link` 创建，兑换由 `/api/ip-limited/share-link/redeem` 完成。

设计规则：

- 所有用户都可以分享。
- 分享被点击一次可触发奖励逻辑。
- 管理员和无限用户不需要增加额度次数。
- 分享奖励归属会随访客注册迁移到用户。

## 删除用户

管理员可以删除普通用户和访客：

- 单个删除：`DELETE /api/web-users/{user_id}`。
- 批量删除由前端逐个调用删除接口。
- 删除用户时会清理对应的额度使用记录。

限制：

- 不能删除管理员。
- 不能删除最后一个管理员。
- 不能把当前登录管理员降级为普通用户。

## 手机端用户管理

手机端保留：

- 用户列表。
- 搜索。
- 用户角色筛选。
- 刷新。
- 退出。
- 全选当前筛选结果。
- 批量删除。
- 所有列通过横向滚动保留。
